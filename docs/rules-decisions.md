# Rules and product decisions

This document separates official physical rules from project-specific decisions. Every entry must
have a status and tests before implementation is considered complete.

## Resolved decisions

### Final-score equality

**Status:** accepted.

When the match ends, every eligible player sharing the strictly lowest cumulative score is a
winner. The result may therefore contain multiple winners.

### Draw-pile exhaustion

**Status:** accepted.

When a draw is requested and the draw pile is empty:

1. keep the current top card of the discard pile in place;
2. move every other discard card into a temporary collection;
3. shuffle that collection using the match random source;
4. use it as the new draw pile.

If the discard pile contains only its top card, the draw action is temporarily unavailable. Taking
the visible discard may still be legal.

### Multiple columns during final reveal

**Status:** accepted and consistent with the official special rule.

After all remaining hidden cards are revealed, remove every complete visible equal-value column
before scoring any player.

### First-round starter tie

**Status:** accepted as a project tie breaker because the official booklet does not define this tie.

Only during the first round, players tied for the highest initial two-card sum are separated by a
server-controlled rock-paper-scissors procedure:

1. each tied player submits a choice privately;
2. choices are revealed only after every remaining tied player has submitted or timed out;
3. if all submitted choices are equal, replay with the same players;
4. if all three gestures are represented, replay with the same players;
5. when exactly two gestures are represented, eliminate the losing gesture;
6. repeat among remaining tied players until one starter remains.

A timed-out rock-paper-scissors choice is generated by the server's random source.

### Starter of later rounds

**Status:** official rule; no custom tie breaker applies.

The player who ended the preceding round starts the next round. Initial revealed-card sums and
cumulative scores are not used for later-round starter selection.

This intentionally rejects the earlier proposal to choose the lowest cumulative score after the
first round, because that proposal conflicts with the normative Magilano rule.

### In-turn timeout

**Status:** accepted at product-policy level; exact duration remains configurable.

A turn has a configurable deadline, initially proposed as 60 seconds. On timeout, the server
chooses one legal command from the player's current phase. The automatic action must continue the
existing turn state; it must not restart the turn or draw a second card.

A player's consecutive auto-play counter:

- increments when a complete turn required server auto-play;
- resets after a complete turn containing at least one valid manual player command;
- causes abandonment after three consecutive auto-played turns.

The random selection is server-authoritative, seedable in tests, and recorded in the event log.

### Voluntary abandonment and connection loss

**Status:** accepted in principle; card disposition and result classification remain unresolved.

Voluntary abandonment, connection timeout, and three consecutive auto-played turns enter the same
player-withdrawal workflow. A later AI module may assume control instead of withdrawing the
player.

The match continues only while at least two real active players remain.

## Unresolved decisions

The following points must be resolved before networking or persistence is implemented:

1. Exact ready-check, connection-loss, and turn durations.
2. Whether a briefly disconnected player receives a reconnection grace period before withdrawal.
3. What happens to a withdrawn player's tableau, pending card, cumulative score, and physical
   cards when no AI replaces them.
4. Whether the last remaining real active player wins by forfeit or the match is recorded as
   aborted.
5. Whether a withdrawn player is always recorded as a loss and excluded from tied winners.
6. How match statistics distinguish disconnect, timeout, voluntary abandonment, and technical
   cancellation.
7. Whether initial two-card selection is automatic or causes ejection when the player times out.
8. Maximum number of rock-paper-scissors replays before a fully random fallback, if any.
